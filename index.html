Percolation: Explanation and Demo

Source Code (Link to Github)

Imagine pouring water onto a layer of soil. At first, the water may only move through a few small spaces. Most paths are blocked, so the water cannot travel very far.

Now imagine that more and more spaces begin to open. Some open spaces connect to each other, but many are still isolated. Then, at a certain point, something important happens: a connected path forms from the top of the system to the bottom. When that happens, the system percolates.

In this project, I model that idea using a square grid. Each square is either blocked or open. The goal is to find out when enough open squares connect together to create a full path across the grid.

This matters because percolation is not only about water. The same idea can describe electricity moving through a material, disease spreading through a population, oil moving through rock, or information traveling through a network. In each case, the main question is the same: when does a connected path appear?

In order to test this, the demo opens random squares in the grid until the system percolates. Each run gives us one estimate of the percolation threshold which is the fraction of squares that had to be open before a full path appeared.

I also ran the Monte Carlo simulations, which means repeating the experiment many times and averaging the results. When comparing the different grid sizes the threshold stayed very close to 0.59. This suggests that percolation has a stable critical point, instead of depending only on one random run.

Behind the scenes, the project uses union-find to quickly keep track of which open squares are connected. Instead of checking every possible path again and again, union-find helps the program update connections efficiently as new squares open.

The demo shows both the visual idea and the algorithmic idea: a random grid slowly changes until one connected path makes movement possible.

Study Report

Percolation: From Theory to Practice

I ran three Monte Carlo simulation studies with 1000 replicates each on 10x10, 20x20, and 50x50 grids. In each replicate, the system started fully blocked, random sites were opened until the grid first percolated, and the fraction of open sites at that moment was recorded as the percolation threshold.

These three studies matter because they show the same phenomenon at increasing scales. The smallest grid is easy to inspect, the medium grid reduces noise, and the largest grid gives the strongest approximation to the large-system behavior predicted by percolation theory.

Grid Replicates Mean Threshold Std. Dev. 95% CI Empirical Runtime
10x10 1000 0.591050 0.073957 [0.586466, 0.595634] 6.894 ms
20x20 1000 0.590683 0.048967 [0.587647, 0.593718] 13.247 ms
50x50 1000 0.593028 0.026394 [0.591392, 0.594664] 61.253 ms

The key result is that all three studies concentrate near a threshold of about 0.59. That consistency supports the theory that percolation has a stable critical point rather than a threshold that depends heavily on one particular random run.

The decreasing standard deviation is also significant. As the grid grows from 10x10 to 50x50, the threshold estimates become tighter, which means the larger grids better reflect the underlying large-scale behavior instead of small-grid randomness.

What is Percolation?

What is Percolation?

Percolation is a simple way to study how things become connected. Imagine water being poured onto the top of a grid. At first, every square is blocked, so the water cannot move anywhere. When you click a square, that site becomes open. Water can move through open squares that touch each other from above, below, left, or right.

In this demo, blue squares are called full. A full square is an open square that is connected to the top row through a chain of other open squares. The system percolates when there is a connected open path from the top row all the way to the bottom row.

This model helps us understand connectivity in random systems. For example, it can represent water moving through soil, disease spreading through a population, electricity passing through a material, or information moving through a network.

How the Computer Tracks Connections

How the Computer Tracks Connections

Behind the scenes, the program keeps track of which open sites are connected. When a new site is opened, it is connected to any open neighbors above, below, left, or right. The system percolates when an open site in the bottom row becomes connected to an open site in the top row.

A common efficient way to implement this is with union-find, also called disjoint sets. Union-find keeps track of which open sites belong to the same connected component, so the program can quickly tell whether a path from top to bottom has formed.

Monte Carlo Simulation

Estimating the Percolation Threshold

Start with every site blocked. Then repeatedly choose one blocked site uniformly at random and open it. When the system first percolates, record the fraction of sites that are open. That fraction is one estimate of the percolation threshold.

By repeating this experiment many times and averaging the results, we get a more reliable estimate. The simulation below reports the sample mean, sample standard deviation, and a 95% confidence interval.

Central Limit Theorem Connection

Each trial of the percolation simulation gives a slightly different threshold because the sites are opened randomly. Some trials percolate earlier, and some percolate later.

The Central Limit Theorem states that when we repeat a random experiment many times, the average of the results becomes more stable and follows an approximately normal pattern. This means that even though one trial may be random, the average threshold from many trials gives a reliable estimate of the true percolation threshold.

Hence, we can use the sample mean and variation from the trials to create a 95% confidence interval. The more trials we run, the more accurate and trustworthy our estimate becomes.

Methodology

Methodology: Pseudocode

Section 1

Initialize the Grid

CREATE grid of size N by N
SET every site to blocked

CREATE union-find structure
CREATE virtualTop node
CREATE virtualBottom node

FOR each site in top row:
    CONNECT site to virtualTop

FOR each site in bottom row:
    CONNECT site to virtualBottom

Purpose: Show that the grid begins completely blocked, and union-find is prepared to track connectivity.

Section 2

Opening a Site

FUNCTION open(row, col):
    IF site(row, col) is already open:
        RETURN

    MARK site(row, col) as open

    FOR each neighbor of site(row, col):
        IF neighbor is inside grid AND neighbor is open:
            UNION site(row, col) with neighbor

Purpose: Show that when a site opens, it connects to nearby open sites.

Section 3

Checking Fullness

FUNCTION isFull(row, col):
    IF site(row, col) is not open:
        RETURN false

    RETURN site(row, col) is connected to virtualTop

Purpose: A site is full if water can reach it from the top.

Section 4

Checking Percolation

FUNCTION percolates():
    RETURN virtualTop is connected to virtualBottom

Purpose: The system percolates when there is a connected open path from the top row to the bottom row.

Section 5

Monte Carlo Simulation

FUNCTION runTrial(N):
    INITIALIZE blocked N by N grid
    openedSites = 0

    WHILE system does not percolate:
        PICK a random blocked site
        OPEN that site
        openedSites = openedSites + 1

    RETURN openedSites / (N * N)

Purpose: One trial estimates the percolation threshold.

Section 6

Repeating Trials

FUNCTION runSimulation(N, trials):
    CREATE empty list thresholds

    REPEAT trials times:
        threshold = runTrial(N)
        ADD threshold to thresholds

    mean = AVERAGE(thresholds)
    stddev = STANDARD_DEVIATION(thresholds)
    confidenceInterval = 95% confidence interval

    DISPLAY mean, stddev, and confidence interval

Purpose: Repeating the experiment gives a more reliable estimate.

Conclusion

For each item, its connected component is the set of all items that are connected to that item.

  • Naive approach: Record every single connecting line somehow.
  • Better approach: Model connectedness in terms of sets.
  • How things are connected isn’t something we need to know.
  • Only need to keep track of which connected component each item belongs to.
